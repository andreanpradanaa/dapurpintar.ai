# AI Development Rules

These rules apply to every task generated by AI.

---

# General Rules

- Follow Clean Architecture.
- Follow Domain Driven Design.
- Follow Modular Monolith.
- Follow all accepted ADRs.
- Never violate bounded contexts.
- Never bypass repositories.
- Never couple unrelated modules.

---

# Documentation Rules

Before generating code:

- Read PROJECT_CONTEXT.md.
- Read the related architecture document.
- Read the related ADR if necessary.

Do not assume undocumented behavior.

---

# Backend Rules

Use:

- Go
- Fiber
- PostgreSQL
- SQLC
- Goose
- Redis

Do not introduce:

- GORM
- Ent
- Bun
- ORM libraries

---

# API Rules

Use REST only.

Version every endpoint.

Example:

/api/v1/...

---

# Database Rules

- SQLC generates queries.
- Goose manages migrations.
- PostgreSQL is source of truth.
- Redis stores temporary data only.

Never:

- Put business data inside Redis.
- Access another module's tables directly.

---

# Domain Rules

Business rules belong to:

- Domain
- Application

Never place business logic inside:

- HTTP handlers
- Database layer
- Middleware

---

# AI Rules

OpenAI is accessed only through the AI Gateway.

Never call provider SDKs directly from business modules.

AI outputs are suggestions, never business truth.

---

# Quality Rules

Always generate:

- Documentation
- Tests
- Error handling
- Logging
- Observability

---

# Security Rules

Never:

- Store secrets in code.
- Log sensitive data.
- Trust client input.

Validate everything.

---

# Code Quality

Prefer:

- Small functions
- Dependency Injection
- Composition
- Explicit interfaces

Avoid:

- Global state
- Circular dependencies
- God objects

---

# Future Scalability

Every implementation should remain compatible with future extraction into microservices without requiring business redesign.
